# MailAssistant

MailAssistant 是面向 Java 课程作业邮件提交的 Windows 桌面工具。它将题目、解答、Java 源码、UML 图和运行截图整理为统一正文，支持预览修改、DOCX 导出和经二次确认的邮件发送。程序不生成作业答案，也不编译或运行导入的 Java 代码。

应用版本：**v1.0.0**。Maven 工件版本为 `1.0.0-SNAPSHOT`，Windows 启动器版本为 `1.0.0`。

## 安装与启动

发布包为自带 Java 运行环境的 Windows 应用目录，无需另装 JDK 或 Maven。将整个 `MailAssistant` 文件夹放在当前用户可写的位置，双击 `MailAssistant.exe`。`app/`、`runtime/` 与启动器必须一起保留，不能只复制 EXE。

- 运行平台：Windows 10/11；用户资料与凭据保护依赖 Windows DPAPI。
- 首次启动在应用目录下创建 `data/`，复制内置题库并初始化本地存储。目录不可写时会报错，不会改用用户目录。
- 同一应用目录只运行一个实例；重复启动会退出第二个进程，原窗口或托盘实例继续运行。
- 主窗口关闭按钮默认隐藏到系统托盘。双击托盘图标恢复窗口；托盘菜单提供「主界面」「个人信息」「草稿箱」「退出」。
- 「个人中心」可创建或更新桌面上的 `MailAssistant.lnk`，并可将默认退出方式改为「直接退出」。托盘不可用时，关闭窗口执行正常退出检查。

## 当前功能

| 功能 | 支持内容 |
| --- | --- |
| 离线题库 | 内置第 1～19 章、173 道编程题；按章节浏览、文字搜索、查看完整题目、勾选题目 |
| 作业编辑 | 文字解答、每题多份命名 Java 源码、UTF-8 `.java` 文件导入、题目排序 |
| 图片与运行结果 | PNG/JPEG 图片；多种运行情况、每种情况多张截图及可选说明、情况和图片排序、UML 图导入 |
| 正文生成 | 自动生成课程主题、身份头、题目与作业内容；生成前检查完整性 |
| 预览修改 | 选择内容块定位预览，编辑可修改文字与图片说明，删除内容块、调整顺序、刷新显示 |
| DOCX 导出 | 将当前预览正文导出为 Word 文档，包含源码、表格、图片与公式图片 |
| 邮件发送 | QQ / 163 发件账号预设、SSL / STARTTLS、SMTP 授权码或已有 OAuth2 Token、HTML 正文与 CID 内嵌图片 |
| 加密草稿 | 命名保存、恢复、确认删除；包含题目与图片快照、代码、运行情况及预览修改，最多保留 30 条 |
| 桌面设置 | 系统托盘、单实例、桌面快捷方式、默认作业目录、退出方式、成功导出或发送后的草稿自动清理 |

题目正文解析支持段落、代码、图片、表格、行内公式和独立公式。题库说明及题目来源记录见 [习题库说明](docs/exercise-bank.md)。

## 使用流程

### 1. 保存个人信息

打开「个人中心」，填写学院、班号、学号和姓名。班号、学号只能输入数字，保留前导零。

仅生成正文、预览或导出 DOCX 时，无需填写邮箱及 SMTP。提交邮件时需要：

- 一个完整的教师邮箱地址；
- 至少一个、最多三个完整的助教邮箱地址；
- 发件邮箱、有效的 SMTP 配置，以及已保存的授权码或 Token。

To 与 CC 不得重复，多个助教地址之间也不得重复。程序没有预填真实收件人。

「默认作业文件夹」为选填项，导入 Java 文件、截图和 UML 时优先打开该目录；目录不存在时使用系统默认位置。「保存设置」会加密保存设置；打开旧草稿不会覆盖全局应用选项。

### 2. 选择章节与题目

在「选择习题」页面选择章节、搜索和勾选题目，查看完整题干后进入「编辑作业」。一份作业只包含同一章节的题目。切换章节会提示清空当前选题，需要保留时先保存草稿。

### 3. 填写代码、解答与图片

每道编程题至少需要一份 Java 源码。通过代码区的圆圈加号添加多份代码，通过每份代码旁的圆圈减号删除。

- 手动粘贴代码时填写代码名称，不必填写 `.java` 后缀，输出时会自动补全。
- 导入 UTF-8 `.java` 文件时自动填入文件名并读取文本；源文件不会作为邮件附件发送。
- 每份保留的代码都必须有名称和内容，输出顺序与添加顺序一致。
- 旧草稿中的单份源码会保留；名称缺失时需补填。

为运行结果添加一种或多种情况，每种情况至少导入一张截图，可填写说明并调整顺序。单一情况不填写说明也有效；空情况需要补图或删除。UML 一般可选，题库中明确要求 UML 的题目必须导入，不能用题目自带的示意图代替自己的作业图片。

图片限制：PNG、JPG/JPEG；单张不超过 10 MiB、2500 万像素；生成正文时，用户提交的运行截图与 UML 图片合计不超过 20 MiB。损坏图片会被拒绝。

### 4. 生成并检查正文

点击「生成正文」。程序检查个人信息、章节、选题、代码名称与内容、运行截图及必需 UML。非编程题的解答也属于必填项。

邮件主题固定为：

```text
Java-学号-姓名-学院-第X章作业
```

正文首行为：

```text
学院-班号班-学号-姓名
```

每题按 **题号与题目 → 解答 / 代码 → UML（若有）→ 运行结果** 排列；各运行情况按设置顺序展示说明及截图。

在预览左侧选择内容块，右侧会滚动到对应位置。可编辑文字和图片说明、删除内容块或上下调整顺序，再点击「刷新预览」检查排版。主题为只读；身份头、题号标题、含行内结构的题库内容及表格不提供直接文本编辑。输出前仍会校验身份头、题目归属、内容顺序、必需源码和截图，不能通过删除必需内容绕过校验。

修改原始作业后，原预览失效，需要重新生成。重新生成已有预览前会确认，因为这会替换预览中的手动调整。单纯切换页面、保存或打开草稿会保留已有预览修改。

### 5. 导出或发送

**导出 DOCX：** 点击导出并选择保存位置。文件使用当前预览中的修改，默认保存对话框指向 `data/export/`。公式以图片呈现，不是 Word 原生可编辑公式；邮件客户端、预览和 Word 的视觉排版可能存在差异。

**提交邮件：** 点击「提交邮件」后再次检查完整性与邮箱配置，在确认窗口核对发件人、教师收件人、助教抄送、主题和题目数量。只有点击二次确认后才连接 SMTP；发送在后台执行并防止重复点击。Java 源码写入正文，图片通过 MIME CID 内嵌，不作为普通文件附件提交。

“服务器已接受此邮件”表示 SMTP 提交成功，不代表收件人已收到或阅读。出现“未能确认发送成功”时，先核对已发送记录和收件情况，再决定是否重试；缺少已发送记录不能单独证明邮件未发出。

## 邮箱配置

在「个人中心」选择 QQ 或 163，仅填写发件地址 `@` 前的账号部分，后缀由程序补全。当前程序预设如下，可在界面中修改：

| 服务商 | 地址后缀 | SMTP 主机 | 端口 | 加密连接 |
| --- | --- | --- | --- | --- |
| QQ | `@qq.com` | `smtp.qq.com` | `465` | `SSL` |
| 163 | `@163.com` | `smtp.163.com` | `465` | `SSL` |

使用 SMTP 授权码时，先在对应邮箱服务商的账户设置中开启 SMTP 并取得授权码，在程序中选择「授权码」认证，将授权码填入「授权码 / Token」，再点击「保存设置」。凭据必须属于当前发件邮箱，不能用 QQ 登录密码替代 SMTP 授权码。SMTP 主机、端口与 SSL / STARTTLS 模式需相互匹配。

- 保存设置只保存本地配置，不连接服务器验证凭据，也不发送邮件；程序没有独立的「测试连接」按钮。
- 再次进入设置时凭据框为空；留空保存会保留当前邮箱已有凭据。更换邮箱后需要保存新账号的凭据。
- OAuth2 接收用户已有的访问 Token，通过 XOAUTH2 认证；不提供浏览器登录授权或 Token 自动刷新。
- 连接强制使用 SSL 或成功升级的 STARTTLS，并验证服务端证书主机名，设置连接、读取及写入超时。

首次验收可使用自己控制的两个不同邮箱作为教师和助教测试收件人，准备完整测试作业并确认发送，然后检查正文、图片和垃圾邮件。该操作会真实发送邮件。正式提交前改回实际收件人、保存设置并重新生成正文；恢复旧草稿后也需核对草稿中的收件人快照。

认证失败时检查 SMTP 服务、认证方式、账号与授权码；连接失败时检查主机、端口、加密方式及网络。自动测试不向真实邮箱发送邮件，真实账号认证与实际投递需要单独验证。

## 草稿与本地数据

点击「保存草稿」可命名，留空按当前系统时间命名；继续编辑后保存会更新同一草稿。草稿箱支持打开和确认删除；超过 30 条时自动清理保存时间最早的草稿。退出时会检查未保存更改；隐藏到托盘不会退出应用。

草稿保存题目、身份与邮箱配置快照、源码、图片字节、运行情况及预览修改，不依赖导入文件的原始路径。移动或删除原始截图不会使已保存草稿丢图。

「草稿自动删除」默认关闭。开启并保存设置后，仅在 DOCX 导出成功或 SMTP 服务器接受邮件后删除对应草稿；取消或失败时保留。删除成功后当前正文仍可查看，继续编辑后可重新保存。清理失败会单独提示，无需重复导出或发送。

运行时目录：

```text
data/
├─ app.lock                         # 单实例文件锁
├─ database/exercise.db             # 运行时只读题库副本
├─ database/backups/                # 题库升级时生成的旧库备份
├─ config/user-profile.enc          # 加密的个人资料和应用设置
├─ config/secrets/master-key.dpapi   # Windows DPAPI 保护的主密钥
├─ config/secrets/smtp-*.dpapi       # 按账号保存的受保护凭据
├─ drafts/<UUID>/draft.enc          # 加密草稿及内嵌图片
├─ export/                          # 默认 DOCX 导出位置
├─ cache/
└─ logs/
```

开发运行时 `data/` 位于项目根目录；普通 JAR 运行时位于 JAR 所在目录；发布版位于 EXE 所在目录。绝对路径系统属性 `mailassistant.home` 可指定应用根目录。

个人资料和草稿使用 AES-256-GCM，每次加密使用独立随机 nonce；主密钥与邮箱凭据由当前 Windows 用户的 DPAPI 保护。导出的 DOCX 是明文文件。将应用复制到其他账户或机器不能保证解密原数据；删除主密钥会使已有加密资料不可恢复。应用不提供跨机器密钥恢复或用户数据自动备份。

「清除此账号凭据与个人设置」删除保存的设置及当前邮箱凭据，保留草稿与其他账号凭据；草稿中仍可能包含旧身份资料。

首次运行提取内置题库。启动时验证题库结构版本、完整性和外键；内置内容版本更新时，先备份旧库再替换运行时题库，保留设置和草稿。相同版本、更高版本及自定义版本不会被覆盖。应用没有题库维护界面，不在线下载题库。

## 源码运行与构建

开发与打包环境：**Windows、JDK 21（含 jpackage）、Maven**。确保 `java`、`mvn`、`jpackage` 可从终端运行。首次构建需要联网下载 Maven 依赖，题库浏览、作业编辑、草稿和 DOCX 导出均可离线使用。

```powershell
# 执行常规测试
mvn test

# 启动开发版
mvn javafx:run

# 清理旧构建，重新打包带 Java 运行环境的 Windows 应用
# target 下的旧发布目录和其中的 data 也会删除，请先处理需要保留的数据。
mvn clean
./packaging/windows/package.ps1
```

打包脚本执行 Maven 测试、生成 JAR、复制运行依赖，再调用 jpackage 生成 `app-image`，不生成安装器，不需要 WiX。默认输出：

```text
target/release/MailAssistant/
├─ MailAssistant.exe
├─ app/
└─ runtime/
```

首次启动前的纯净应用目录不包含 `data/`、个人资料、凭据或草稿。发布时需分发整个目录。JAR 位于 `target/mail-assistant-1.0.0-SNAPSHOT.jar`，它依赖相邻运行库，不能单独当作完整发行包。

脚本拒绝覆盖已有 `MailAssistant` 发布目录。可用 `-Destination target/release-next` 指定其他输出目录；`-SkipTests` 可跳过测试，默认构建执行测试。

图形环境下的界面冒烟测试会短暂打开使用虚拟资料的测试窗口，截图写入 `target/ui-smoke/`，不连接 SMTP：

```powershell
mvn test "-DuiSmoke=true"
```

测试覆盖正文与 DOCX、MIME 邮件、完整性校验、加密资料及草稿、设置、单实例、题库升级和桌面行为。更详细的操作与开发说明见 [开发与运行](docs/development.md)，图标和托盘实现见 [桌面集成](docs/desktop-integration.md)。

src/main/java/com/mailassistant/
├─ application/       # 用例协调、正文生成与发送流程

├─ mail/              # SMTP、MIME 与服务商预设
├─ preview/           # 统一正文模型与 HTML 渲染
├─ repository/        # 数据访问接口
├─ security/          # AES-GCM、DPAPI 与账号凭据
